# Exercise — Generate `dbt docs`

## Goal

Run `dbt docs generate` and confirm the docs artifacts land in `target/`. Optionally serve the site and click around — but the verifier only checks that the artifacts exist and were updated by this run.

## Steps

**1.** From the repo root:

```bash
cd dbt_project
```

**2.** Generate the docs site:

```bash
dbt docs generate
```

Output should end with a line like:

```
Catalog written to target/catalog.json
```

That's the new file — column-level metadata pulled by introspecting your DuckDB tables. `target/manifest.json` was already up-to-date from the `dbt build` you ran in the previous exercise.

**3.** (Optional) Serve the site and browse:

```bash
dbt docs serve --port 8080
```

Your browser should open to `http://localhost:8080`. Click into:

- The **lineage button** (bottom-right of the page) — see Stage 2's whole DAG: two green source groups (`jaffle_shop`, `stripe`), three staging views, the intermediate, the fact.
- A **model page** like `fct_orders` — switch between the **Details**, **Columns**, and **Compiled** tabs. The Compiled tab shows the actual SQL dbt sent to DuckDB, with all `{{ source(...) }}` / `{{ ref(...) }}` macros expanded.
- A **source page** like `jaffle_shop.raw_customers` — column types pulled from DuckDB.

Press `Ctrl+C` to stop the server when you're done.

**4.** Confirm both artifacts exist and were just touched:

```bash
ls -la target/manifest.json target/catalog.json
```

Both should be very recent.

**5.** Press `v`.

## What the verifier checks

- `dbt docs generate` (run by the verifier) exits 0.
- `target/manifest.json` exists and was regenerated by this run (mtime is current).
- `target/catalog.json` exists and was regenerated by this run.

If either file is missing or stale, the verifier fails — the most common cause is the warehouse being unreachable (DuckDB file deleted) or `dbt parse` choking on a YAML error.

## Common failure modes

| Symptom | Fix |
|---|---|
| `Could not connect to database` | DuckDB file is missing or locked. Run `dbt build` first to recreate it; close any other process that has the file open. |
| `dbt: command not found` | Activate the venv: `source .venv/bin/activate`. |
| `Address already in use` on `dbt docs serve` | Another `dbt docs serve` is still running, or another app owns port 8080. Use `--port 8081`. |
| `catalog.json` missing after the run | `dbt docs generate` requires query access to introspect tables. If it skipped the catalog with a warning about `Skipping catalog generation`, fix the warehouse connection first. |
